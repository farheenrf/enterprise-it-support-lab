# Lab 01: Microsoft Entra User and Group Management

## Scenario

Simulated onboarding a new Help Desk Analyst in a Microsoft Entra environment using a fictional test identity.

## Tasks Completed

- Created a fictional cloud user named Alex Morgan
- Configured the user as an internal member
- Added job title and department information
- Left the account without administrative roles
- Left the account unlicensed to avoid unnecessary costs
- Created an assigned security group named `LAB-ServiceDesk`
- Added Alex Morgan as a group member
- Assigned an authorized administrator as the group owner

## Validation

- Confirmed that the test user appeared in Microsoft Entra ID
- Confirmed that the account was enabled
- Confirmed that `LAB-ServiceDesk` was created as a security group
- Confirmed that Alex Morgan appeared in the group membership list

## Security Practices

- Used a fictional identity
- Followed least-privilege principles
- Did not assign an administrative role
- Did not assign a paid Microsoft 365 license
- Did not publish passwords, tenant IDs, object IDs, email addresses, or business-domain information

## Skills Demonstrated

- Microsoft Entra ID administration
- User onboarding
- Security-group management
- Role-based access planning
- Identity and access management
- Enterprise IT support documentation
